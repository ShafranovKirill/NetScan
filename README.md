# NetScan

Русскоязычное приложение для поиска HTTP-прокси и проверки доступа в интернет. Linux (Fedora, Debian/Ubuntu) и Windows, без изменения системных настроек сети.

## Установка

Готовые RPM, DEB, AppImage, Windows Setup EXE и portable ZIP публикуются в [Releases](https://github.com/ShafranovKirill/NetScan/releases). Первые версии не подписаны цифровой подписью.

- Fedora: `sudo dnf install ./NetScan-0.2.1-x86_64.rpm`
- Debian/Ubuntu: `sudo apt install ./NetScan-0.2.1-x86_64.deb`
- AppImage: разрешите запуск файла в его свойствах и откройте. При отсутствии FUSE запускайте с `--appimage-extract-and-run`.
- Windows: откройте Setup EXE; права администратора не требуются. Portable ZIP нужно распаковать целиком.

## Использование

1. Откройте раздел «Подсети». Введите IPv4-адрес и отдельную маску (по умолчанию `/24`), для одного устройства нажмите «Один IP» (`/32`). Можно импортировать UTF-8 TXT: одна подсеть на строку. `10.0.4.1/24` автоматически превращается в `10.0.4.0/24`.
2. Перетащите строки или используйте кнопки вверх/вниз: верхние сети проверяются первыми. Подсети обрабатываются последовательно; адреса внутри каждой — параллельно.
3. В разделе «Параметры» укажите порт (по умолчанию 3128), параллельность, таймаут и лимит **рабочих** прокси. Ноль означает без ограничения.
4. При необходимости введите учётные данные прокси или загрузите сохранённый локальный профиль. Они отправляются только после HTTP 407 и запроса схемы Basic. NTLM, Digest, Kerberos и вход через веб-портал пока не поддерживаются. Для Basic используйте доверенные прокси: соединение до HTTP-прокси не зашифровано.
5. Запустите поиск. «Интернет проверен» означает успешные HTTPS-запросы к Google (`/generate_204`, ожидается 204) **и** Example.com (ожидается 200 и маркер страницы), с проверкой TLS-сертификатов. Это не гарантия доступа ко всем сайтам.
6. Можно поставить поиск на паузу, остановить его, скопировать адрес, перепроверить найденные результаты и экспортировать CSV. Фильтр «Только рабочие» действует и при экспорте.

Пароль не записывается в обычные настройки, журналы или CSV. При явном сохранении профиля он хранится в системном хранилище паролей: Secret Service в Linux, Credential Manager в Windows. Учётные данные не встроены в исходники или публичные установщики. Список подсетей сохраняется локально в настройках пользователя. Автоматического сканирования при запуске нет. Системные прокси, адреса, маршруты, DNS и Throne не изменяются. Переменные окружения прокси игнорируются; существующие VPN/TUN и политики маршрутизации ОС продолжают действовать.

Пауза прекращает запуск новых проверок; уже начатые завершаются. Остановка ждёт текущие запросы в пределах их таймаутов. Лимит N прекращает выдачу результатов после N подтверждённых прокси, но уже запущенные запросы могут завершиться. При закрытии окна во время поиска сначала выполняется остановка; затем окно можно закрыть повторно.

За запуск — до 65 536 адресов и до 64 параллельных проверок (по умолчанию 12). Используйте только согласованные диапазоны. Рабочие адреса и учётные данные вашей сети не включены в репозиторий.

## Разработка

Python 3.11+:

```sh
python3 -m venv .venv
# Linux
source .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -e '.[dev]'
python -m netscan
```

Проверки: `QT_QPA_PLATFORM=offscreen python -m pytest -q` (Linux). Сборки и лицензии зависимостей описаны в [packaging/README.md](packaging/README.md). Qt/PySide6 распространяется в составе приложения с уведомлениями и лицензиями сторонних компонентов.
